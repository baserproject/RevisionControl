# RevisionControl

固定ページ・ブログ記事の編集履歴（リビジョン）を保存し、過去の状態に戻すことができる baserCMS 用プラグインです。

## 特徴

- 固定ページ・ブログ記事の保存時に、その時点のデータを履歴として自動保存します
- 編集画面のフォーム末尾に履歴一覧（保存日時・更新ユーザー）を表示し、リンクから過去のリビジョンを編集画面に読み込めます
- ブログ記事のアイキャッチ画像もリビジョンごとに退避します
- 履歴の世代数に制限を設けられます（超過した古い履歴は自動削除）

## 動作要件

- baserCMS 5.3 以上（CakePHP 5.2 / PHP 8.1 以上）

## インストール

`plugins/RevisionControl` に配置し、管理画面の「プラグイン管理」から有効化します。

## 保存データについて

- 固定ページは本文・テンプレート・コードのみが履歴管理され、基本設定・オプション・関連コンテンツなどは対象外です
- ブログ記事のアイキャッチをリビジョンごとに保存するため、データ容量が大きくなる場合があります。容量に余裕が無い場合は世代制限を設けて利用してください

## 設定（config/setting.php）

| キー | 内容 |
| --- | --- |
| `limit` | 世代制限。超過した古い履歴を自動削除（`0` で無制限。既定 `50`） |
| `displayLimit` | 履歴一覧の表示件数（既定 `20`）※現状のコードでは未参照（一覧は全件表示） |
| `models` / `views` | 履歴対象のモデルと編集画面の対応（既定: 固定ページ・ブログ記事） |
| `actsAs` | アップロードファイル（アイキャッチ等）を退避する対象フィールド |
| `excludeFormId` | 履歴一覧を表示しないフォーム ID（同一画面の別フォームでの重複表示防止） |

### 対象履歴の追加について（製作者向け情報）

`models` / `views` の設定値を変更すると、他のプラグインのデータについても履歴対象に追加することが可能です。

## 開発

### ユニットテストの実行

本プラグインは単体（standalone）でテストを実行できます。

1. 依存パッケージをインストールします（プラグインディレクトリで実行）。

    ```shell
    composer install
    ```

2. テスト用の DB 接続情報を設定します。`.env` は gitignore 対象です。

    ```shell
    cp tests/TestApp/config/.env.example tests/TestApp/config/.env
    ```

    `.env` を実行環境の値（DB ホスト・ユーザー・パスワード・データベース名）に書き換えます。
    データベース名を省略した場合の既定値は `revision_control`（`DB_NAME`）/ `test_revision_control`（`DB_TEST_NAME`）です。

3. テスト用データベース（`Datasources.test` のデータベース）を作成します。

    ```sql
    CREATE DATABASE `test_revision_control` CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
    ```

4. テストを実行します。スキーマは Migrations（BaserCore ＋ BcBlog ＋ 本プラグイン）から自動構築されます。

    ```shell
    vendor/bin/phpunit
    ```
